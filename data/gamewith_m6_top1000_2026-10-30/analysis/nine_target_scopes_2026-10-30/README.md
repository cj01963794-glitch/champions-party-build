# M6 9종 포켓몬별 상대 조합 검토 범위와 해석 메모

> 2026-10-30 · 출처: GameWith M6 수집 파티 296개 중 6마리 완전 공개 285개. **사용자가 직접 대면 성능 검증·파티 구축**, 이 문서는 6마리 구성 통계와 검토 범위만 제공한다.
> [필수 원칙](../../../../docs/COMBINATION_BASELINE_PRINCIPLE.md): A+B+C가 자주 나타난다는 이유만으로 A 특유 조합이라고 판단하지 않는다. A 비채용군의 **B+C 동시 채용률**을 기준선으로 삼는다.

## 분석 방식

- A는 검토 대상 포켓몬, B+C는 나머지 두 포켓몬의 **한 쌍**. 모든 6마리 완전 공개 파티를 원본 기록 그대로 1건씩 센다(동일 6마리의 중복 등재도 별도 건수).
- x = `A+B+C`가 있는 파티 수, y = A 없는 파티에서 `B+C`가 함께 있는 파티 수. `RR=(x/nA)/(y/n0)`; `기대=nA*y/n0`; `초과=x-기대`. 미채용군 y=0은 배율 계산 불가로 표시한다.
- q = A마다 가능한 B+C 7,260쌍 **전체**의 Fisher 양측검정 p값을 BH 다중비교 보정한 값. q<0.05만 '통계적으로 유의'로 구분한다. 표본/측정 구조가 작거나 중복된 파티 구성이 많으면 여전히 해석에 주의한다.
- **주요/보충 검토 범위는 원본 조합 탐색을 위한 목록이지 3대3 선출 추천이나 성능 순위가 아니다.** 여러 A+B+C가 하나의 6마리 파티를 동시에 가리키므로 포괄률은 고유 파티 기록 기준으로 중복 제거한다.
- 6마리 목록만으로 메가진화 형태, 기술배치, 실제 3마리 선출, 승률, 카운터를 확정하지 않는다. 과거 M6 자료가 현재 시즌 전체를 대표한다고 보장하지 않는다.

### 분석 코멘트

- 플라엣테+대검귀+한카리아스(7회)는 기본 채용률을 고려해도 상대적으로 여러 번 결합한 사례이지만 전체 6마리 고유 구성 수는 5종이다. 대검귀+타부자고와 더시마사리+한카리아스는 해당 파티들의 뒷면 구성과 겹칠 수 있어 중복 제거가 중요하다.
- 오롱털+타부자고(4회) 등은 비채용군 동반이 0회인 희소 조합이다. 특히 66·79·289·573위 사례는 실제 고유 6마리 구성 2종에 불과하므로 원시 랭크 횟수를 독립적인 네 가지 구축으로 해석하지 않는다.
- 아머까오+한카리아스(9회) 및 타부자고+한카리아스(8회)는 노출이 높은 묶음이다. 통계적으로 뚜렷한 '플라엣테 특화' 판정은 다중검정 이후 확인되지 않으며, 핫삼·브리두라스·보만다 등의 보충군으로 범위를 넓혀 확인한다.

**이 문서의 주요+보충 목록에 포착되지 않는 파티:** 99위, 178위, 216위, 236위, 250위, 292위, 522위, 645위. 이 역시 6마리 전체 원본과 함께 `all_target_parties.csv`에 포함돼 있다.

## 파일 안내 및 검증

- `all_target_parties.csv`: 9종 각각이 들어간 전체 6마리 파티의 순위·플레이어·원본 위치·선택 묶음 포함 여부. 여러 기준 A가 같은 파티에 들어 있으면 각 기준에 중복 기재.
- `all_observed_target_triples.csv`: 9종별 실제 등장한 모든 A+B+C에 대한 조건부 분모와 관찰 횟수, 비채용군 기준선, Fisher p, A당 7,260개 검정의 BH q, 고유 6마리 수, 원본 순위. 미등장 조합은 저장하지 않지만 BH 보정 시에는 모든 후보를 포함함.
- `selected_scope_complements.csv`: 위 주요+보충 범위의 **모든** 출현 랭크별 나머지 D+E+F (중복 교차 포함).
- `selected_scope_statistics.csv`: 위 주요+보충 묶음만 별도 추출한 간편 조회 표.
- `manifest.json`: 9종별 원본 파티 수, 검사한 후보 조합 수, 선택 묶음의 중복제거 포괄률과 검증용 합계.

**한계:** 사용률·조합의 연관성은 실제 3마리 선출, 행동 순서나 카운터로 자동 변환되지 않는다. D+E+F는 원본 6마리를 3+3으로 나눈 '남은 멤버'이며 **실제 비선출 3마리**라는 뜻이 아니다. 파티 구축·대면 검증은 사용자에게 맡긴다.
