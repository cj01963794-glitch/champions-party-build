# M6 통합 조합 통계 데이터베이스 (2026-10-30)



> **전 포켓몬 공통 필수 분석 원칙:** 3마리 조합 A+B+C를 'A의 특징적 조합'으로 소개하기 전, **A를 사용하지 않는 파티에서 B+C가 동시에 등장하는 비율**과 비교해야 한다. 단순한 ABC 출현 빈도 상위는 특징적 결합의 증거가 아니다. RR·기준선 기대횟수·초과 출현·표본 수·불확실성을 함께 제시한다. 구체적 규칙과 갑주무사 반례: [조합 기준선 비교 원칙](../../../docs/COMBINATION_BASELINE_PRINCIPLE.md).

원본: [GameWith M6 상위 296개 파티](../parties.csv). 6마리 전원이 공개된 **285개** 파티만 포함한다. 6마리 완전 동일 중복 파티도 별도 순위 기록으로 센다(고유 6마리 세트 272종).

- **1번:** `triple_statistics.csv` — 3902개의 실제 관찰된 3마리 조합별 출현 횟수, 순위, 구간별 빈도.
- **2번:** `triple_complements.csv` — 285개 파티 × 20개 가능한 3마리 부분집합 = **5,700개** 방향 있는 ABC→DEF 기록. `triple_complement_counts.csv`는 요약 집계. 이는 실제 선출 기록이 아니라 6마리 팀을 3+3으로 분리한 **가상의 구성**이다.
- **3번:** `pokemon_usage.csv`와 `pair_statistics.csv` — 총 7381개 가능한 2마리 조합(미등장 조합도 0 포함), 채용률·양방향 동반률·양방향 비채용군 대비 배율·Lift·Fisher 양측검정·전체 쌍 BH 보정. `conditional_pairs.csv`와 `conditional_triples.csv` — 2마리/3마리를 고정한 뒤 나머지 포켓몬들의 조건부 채용과 기대 대비 초과. 
- **4번:** 각 통계 파일의 `rank_list`와 `top_50 / rank_51_100 / rank_101_300 / rank_301_1000`; 원본의 실제 순위 값만 사용한다. 순위가 비는 것은 원본에 해당 순위의 파티가 없기 때문이다.
- **5번:** `triple_neighbors_by_shared_pair.csv` — 공통 2마리를 가진 세 마리 조합을 빠르게 비교할 수 있는 역인덱스. 같은 `shared_pair` 아래의 다른 `third_pokemon`은 한 마리만 다른 3마리 조합이다.

## 통계 의미

- `relative_rate` = P(대상 포켓몬 | 앵커 포함 팀) ÷ P(대상 포켓몬 | 앵커 미포함 팀). `INF`는 비교군 채용 0건으로 나눗셈 불가인 상황이며, 무한한 실전 효과를 뜻하지 않는다.
- `lift` = P(앵커와 대상 동시 채용) / (P(앵커 채용) × P(대상 채용)). 조건부 분석에서 앵커는 2~3마리 묶음이다.
- `expected_from_outside` = 앵커를 쓰지 않은 팀의 대상 채용률 × 앵커 포함 팀 수. `excess_from_outside` = 실제 공동 채용 횟수 - 이 기대값.
- p값은 2×2 표 양측 Fisher 정확검정, q값은 Benjamini–Hochberg 보정. `q_bh_per_anchor`는 앵커별 전 포켓몬을 포함한 비교군, `q_bh_across_level`은 같은 앵커 크기(2 또는 3)의 테스트 전체를 보정한 값이다.
- 앵커 지원 파티 수가 **3 미만**일 때 검정은 생략하며 `low_support`로 표시한다. 조건부 CSV에는 **공동채용 1건 이상 또는 전체 테스트의 보정 q<0.05인 0건**만 저장한다. 빠진 조합의 공동채용 횟수는 0이며, 유의성은 저장된 CSV만으로 임의 추정하면 안 된다. 필요 시 재계산 프로그램으로 질의한다.
- 중복 파티, 포켓몬 종 자체의 인기, 수집 편향, 미공개 멤버로 인한 영향을 분리해 생각해야 한다. **공동 채용 ≠ 실제 동시 선출 ≠ 대면에서의 시너지/승률.** 메가진화 형태 및 기술배치는 원본의 6마리 목록만으로 확정하지 않는다.

## 검증

검증용 `manifest.json`에 11개 항목의 자동 검증 결과와 집계 규모를 저장했다. 원본 296개 중 완전 공개 285개, 2마리 출현 총 4275건, 3마리 출현 총 5700건, 방향 있는 3+3 대응 5700건. 동일한 6마리 조합을 하나로 합치지 않고 원본 기록 그대로 집계했다.

## 재계산 및 파일 조회

```bash
cd data/gamewith_m6_top1000_2026-10-30/analysis
python build_database.py
python shard_csv.py
```

Python 표준 라이브러리만 사용한다. `build_database.py`는 바로 위의 `parties.csv`에서 통계 CSV 8개와 `manifest.json`을 다시 생성하고, 11개 무결성 검사를 실패 시 중단한다. `shard_csv.py`는 대용량 CSV 3개의 조회용 조각을 `shards/` 아래에 생성한다. **분할 CSV는 별도의 추가 표본이 아니라 동일한 데이터의 조회용 복제본**이다.

모든 확률과 p/q값은 CSV에서 소수점 여덟 자리까지 기록된다. 따라서 `0`으로 표시된 매우 작은 p/q값은 수학적으로 정확히 0이라는 뜻이 아니라 저장 정밀도 아래라는 의미다. 더 높은 정밀도가 필요하면 재계산 코드를 수정해 산출해야 한다.
