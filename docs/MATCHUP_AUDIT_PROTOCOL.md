# 주요 상대 파티별 선출·승리 플랜 검증 절차

> 작성일: 2026-10-28 (KST)  
> 상태: 사용자 지시에 따라 채택한 필수 구축 검토 절차  
> 현재 데이터: 사용자 제공 예정. **아직 개별 상대 파티를 검증한 것으로 간주하지 않는다.**

## 목표

사용자가 제공할 **랭커 파티 및 환경에서 유행하는 모든 대상 파티**를 누락 없이 등록하고, 각 파티마다 사전에 검토된 선출 계획 및 승리 플랜이 존재하는지 확인한다.

이때 **선출 계획의 존재**와 **그 상대에 대한 유리함**은 서로 다른 판단이다. 불리한 상대라도 어떤 조건을 노려야 승리 가능한지 설명해야 하고, 경로를 찾지 못했다면 숨기지 않고 미해결로 표시한다.

## 검토 단위

- 상대의 **실제 파티 전체**가 검토 단위다. 독립적인 개별 포켓몬과의 1대1 대면 결과만으로 완료 처리하지 않는다.
- 입력에 포함된 각 파티는 자체 ID, 출처, 수집 날짜, 포켓몬 여섯 마리, 알려진 기술/아이템/특성/노력치/변형 등을 보유한다.
- 하나의 팀에 서로 다른 주요 선출·기술배치가 있다면 중요한 변형을 분리해 검토한다.
- 정보가 없는 요소는 **미상**으로 표시하며 임의로 채워 넣지 않는다.
- 대상 범위는 사용자로부터 전달받은 자료 및 이후 합의한 추가 자료로 규정한다. 새로운 파티가 추가되면 목록과 검토 상태를 갱신한다.

## 상대 배치의 불확실성 검토 (모든 대상 파티 공통)

대표형을 기준으로 첫 선출 및 승리 계획을 만든 뒤, 상대의 **아이템, 기술, 수치 조정, 대체 선출**에 따라 계획이 깨지는지 시험한다.

- 후보를 단순히 전수 나열하지 말고, **선공 관계 변경 / 행동 보장 / 방해 기술 회피 / 피벗 / 회복·난수 임계값**처럼 승패에 영향을 주는 기능으로 분류한다.
- 상대의 도구·4개 기술 슬롯 및 세트 내 다른 기능의 기회비용을 고려한다.
- 선출 시 보이지 않는 배치를 정확하게 알고 있다는 전제의 분기는 인정하지 않는다.
- 채용 비중이 낮더라도 **정상적인 승리 계획을 붕괴시키는 변형**은 검토한다. 다만 그 대응을 위해 다른 핵심 파티에 약해지는지를 함께 본다.
- 결과는 **대표형 검증, 영향 큰 변형 검증, 잔여 위험**으로 나누어 남긴다.
- 예시 목록에 과도하게 매달리지 않는다. 더 자세한 원칙은 [SET_VARIANT_ANALYSIS.md](SET_VARIANT_ANALYSIS.md).

## 대응책의 실전 채택 비용과 완성된 상대 상태에 대한 검증

'막을 수 있는 기술이 존재한다'는 사실만으로 대응 가능이라고 판정하지 않는다.

- 상대의 **실제 기점 생성/턴 확보/스윕 완성**을 수순으로 묘사하고, 그중 무엇을 막아야 하는지 먼저 판단한다.
- 막기 전 단계와 이미 상대의 랭크업이 완성된 단계를 구분한다. 후자는 단순 타입 상성보다 **정확한 체력·피해·회복·속도·PP 및 변화 상태**를 확인한다.
- **메가진화 전후 특성/타입**의 차이가 있으면 진화 시점과 선택 이유를 명시한다.
- 후보 대응책은 **어느 아군이 어떻게 채용하고, 실제 3마리 선출에 넣을 수 있고, 포기하는 기술/포켓몬 역할은 무엇인가**까지 분석한다.
- 특정 대책을 한 상대를 위해 억지로 배정했을 때 **비파티/사이코필드/다크펫 등 다른 주요 대면에 발생하는 손실**과 비교한다.
- 일반적인 대응 방법이 무력화되는 **타입·특성·기믹의 조합**은 상대 전략의 핵심 장점으로 본다. 남은 예외적인 방법의 실제 채용 가능성과 사용 비용도 비교한다.
- 기믹 자체를 길게 열거하지 말고, 해당 대면에서 **승리/패배 판정을 바꾸는 정보** 위주로 분석한다.

## 신규 대책 제안 시 변경 전후의 순증가 가치 검토

- **기준선 구축:** 현재 아군 6마리/기술/아이템으로 해당 상대를 어떻게 상대하는가? 이미 충분히 이기는 상대를 추가 저격할 가치가 있는지부터 판단한다.
- **변경안 구축:** 포켓몬 한 자리 또는 기술 한 칸을 바꾸면 실제 어떤 선출/승리 수순이 개선되는가?
- **대체 비용:** 빠진 포켓몬/기술이 담당했던 대면을 누가 대신 담당하는가? 다른 주요 파티에서 이전보다 유리해지는지 불리해지는지 비교한다.
- **6→3 실현성:** 카운터 포켓몬이 여섯 마리에 있다고 해서 해당 3마리 선출로 전체 상대 6마리를 이긴다고 선언하지 않는다.
- **환경 비중:** 실제 관측된 파티 유형 비중을 고려하되, 데이터 없이 임의의 수치·기댓값을 만들지 않는다.
- **필수 통과군 우선:** 필수 아키타입의 구조적 결함을 환경 평균 승률로 상쇄하지 않는다. 그러나 저격 전용 슬롯을 자동으로 강제하지는 않는다.

- **조건부 역할 집중 허용:** 이미 채용한 포켓몬이 다른 다섯 마리의 대면 공백을 메우는 전문화가 최선일 수 있다. 개별 포켓몬이 범용적이지 않다는 이유만으로 탈락시키지 않는다.
- **검토 수준 분리:** 현 여섯 마리의 역할을 재분배하는 기술배치 최적화와, 여섯 마리를 갈아엎을 수도 있는 구성 최적화를 다른 판단으로 기록한다.
- 더 좋은 전체 구조가 가능하다는 것은 **검증 대상**이지, 지금 실행 가능한 합리적 차선책을 지우는 자동 판정이 아니다.

자세한 기준: [COUNTERMEASURE_MARGINAL_VALUE.md](COUNTERMEASURE_MARGINAL_VALUE.md).

## 별도 필수 통과군: 대표적인 정형 전개파티

사용자가 지정하는 대표적인 **'뇌사 전개파티'**는 일반 환경 파티와 달리 **필수 통과군**으로 분류한다. 이 부류는 상위권에서 사용률이 낮더라도, 널리 알려진 대책을 갖추는 것이 비교 대상인 랭커 파티의 기본 전제일 수 있다.

- 등록 즉시 `MATCHUP_REGISTRY.md`에서 **필수-전개**로 구분한다.
- 아래 7단계 검토에 더해, 합리적 상대 운용에 대한 **압도적이고 견고한 대응**을 확인한다.
- 구조적인 일반 패배 수순이 남으면 실패/미해결로 표시한다. 출현 비중이 적다는 이유로 통과 기준을 완화하지 않는다.
- 확인할 수 없는 급소·명중·난수·상대 변형 등의 위험은 따로 적되 100% 보증인 것처럼 표현하지 않는다.
- 관련 절차: [REQUIRED_SETUP_MATCHUPS.md](REQUIRED_SETUP_MATCHUPS.md).

## 각 파티의 일곱 단계 검토

### 1. 상대의 구조와 승리 전략 파악

- 상대의 역할 분담, 핵심 조합, 주된 압박 및 봉쇄 수단 분석.
- 알려진 대표 선출, 선봉, 전개 및 승리 조건 기록.
- 구체 기술배치나 특성이 미확인일 경우 불확실성을 기록.

### 2. 우리 파티를 본 상대의 선출 선택 고려

- 상대가 일반적으로 선출하는 조합과 **우리 6마리를 상대로 유도되는 선출**을 구분.
- 상대의 합리적인 대체 선출과 특정 대응 포켓몬 보유 여부 검토.
- 상대의 선출이 공개되기 전의 정보만 이용해 판단한다.

### 3. 아군 선출안 확정

- 실제 룰에서 선출할 수 있는 **선봉 및 후속 포켓몬**을 명시.
- 각 포켓몬의 역할과 그 외 선택지를 배제한 이유 기록.
- 하나의 정답 조합을 강제하지 않는다. 조건부 선출 정책과 대안을 허용한다.
- 아군의 선출을 결정하는 시점에 알 수 없는 정보를 확정 사실로 가정하지 않는다.

### 4. 승리 플랜 전개

- 우선 제거·무력화할 상대 요소, 확보할 전개 조건, 자원 소모, 마무리 포켓몬을 구체화.
- 교체·선공기·기술 잠금·랭크업·체력 구간·확률적 분기 등 실제 성립 조건을 명시.
- 막연히 “유리한 대면을 만든다”라는 식의 설명만으로 완료 처리하지 않는다.

### 5. 상대의 합리적인 대응에 대한 반증 시도

- 우리가 원하는 대로 행동해주는 상대를 가정하지 않는다.
- 상대가 다른 선봉을 택하거나 교체/선공기/보존/자원 교환 등으로 방해할 때 플랜이 어떻게 바뀌는지 검토한다.
- 승리 경로의 주요 취약점, 필요한 예측, 난수 의존성, 회복 및 기술 PP와 같은 소모를 구체화.

### 6. 예상과 다른 정보의 등장에 따른 전환

- 상대 선출이나 기술이 드러났을 때 플랜 변경이 가능한지 확인.
- 미확인 배치까지 모두 카운터한다고 단정하지 않으며, 각각의 정보 제한과 대응 범위를 적는다.
- 기본 플랜이 깨질 경우 대체 수순 또는 손실 최소화 전략을 기록한다.

### 7. 결론 및 후속 조치

- **상성 평가:** 유리 / 대등 / 불리 / 판정 보류 (근거 필수).
- **계획 상태:** 검증 완료 / 조건부 검증 / 미해결 / 정보 부족.
- 플랜의 구체적 실행 가능성과 반례를 기록한다. 단순히 “승리 확률이 0보다 큼”은 충분하지 않다.
- 이 대면 때문에 파티의 포켓몬·기술·아이템·노력치·선출 구조를 수정할지 결정한다.
- 수정되면 이미 완료한 다른 상대 파티에 대한 계획이 깨지지 않는지 **재검증**한다.

```markdown
- 미확인 정보 및 주요 변형:

- 대체 선출 / 대체 플랜:

- 기존 구축과 변경안의 차이 / 새로 얻는 승리 경로 / 포기하는 승리 경로:
- 위험 요소(예측, 난수, 공개되지 않은 배치):
- 평가: 유리 / 대등 / 불리 / 판정 보류
- 필수-전개라면 통과 여부 및 정상적인 패배 수순 유무:
- 계획 상태: 검증 완료 / 조건부 검증 / 미해결 / 정보 부족
- 파티 수정 필요 여부 및 이유:
- 마지막 검토일 / 검토한 아군 파티 버전:
```

## 검증 완료의 기준

1. 실제 가능한 선출이 명시됨.
2. 그 선출의 이유가 상대 **파티 전체와 전략**을 기준으로 설명됨.
3. 실현 가능한 승리 조건과 주요 행동의 연계가 구체적임.
4. 적어도 대표적인 합리적 상대 선출·운용에 대해 반증을 시도함.
5. 예상과 다른 상황에서 어떤 정보로 플랜을 전환할지 기술됨.
5a. 실제로 승리 계획을 뒤집는 합리적인 세트 변형의 존재와 잔여 위험을 검토함.
6. 명확한 불리함이나 미확인 요소를 숨기지 않고 기록함.

충족하지 못하면 완료가 아니다. **전체 목록의 검토 완료**와 **모든 매치업 유리**는 동일하지 않다. 전자는 구축의 계획·설명 가능성에 대한 검증이고, 후자는 훨씬 강한 성능 주장이다.

## 전체 목록 검토 시 운영 규칙

- 상대 파티가 입력되는 대로 `docs/MATCHUP_REGISTRY.md`에 한 건도 빠짐없이 등록한다.
- 각 파티의 개별 검토 문서는 추후 `docs/matchups/` 하위에 저장한다.
- 목록 안에 있는 모든 파티의 상태를 확인해 **미검토/미해결 항목을 볼 수 있게** 한다.
- 파티 수정 또는 상대 메타 변화 시 영향받은 검토 항목을 다시 열어 검증한다.
